# VortenaBot — исправления и проверка

## Исправлено в этой сборке

1. **Кнопка «⏱ Интервал» в главном меню не открывала настройку интервала.** В главном роутере проверялось только старое название «⏳ Интервал», хотя клавиатура показывала «⏱ Интервал». Теперь поддерживаются оба варианта.
2. **Повторный запрос кода Telegram.** В `bot.py` импортируется `functions`, а обработчик вызывает `functions.auth.ResendCodeRequest`. Он не отказывает локально только потому, что `next_type` отсутствует; ответ и ошибки Telegram обрабатываются отдельно.
3. **Номер телефона.** Используется международный формат и распознавание `00`, `+992`, `+7`, а неоднозначные 10-значные номера больше не преобразуются автоматически в российские.
4. **Ошибки отправки в группы.** `sender.py` обрабатывает ошибки по каждой группе отдельно и продолжает список; ошибки доступа и FloodWait записываются в результат.
5. **Конфигурация и схема БД.** Сохранены переменные окружения и добавочные миграции схемы из исходной сборки.

## Проверки, выполненные локально

- `ast.parse` и `py_compile` для `bot.py`, `sender.py`, `db.py`, `config.py`.
- ZIP integrity test.
- Проверка наличия обработчика для каждой кнопки главного меню, включая «⏱ Интервал».
- Проверка, что `functions.auth.ResendCodeRequest` имеет соответствующий импорт.

## Ограничения

Это статическая проверка. Здесь нет ваших реальных `BOT_TOKEN`, `API_ID`, `API_HASH` и `DATABASE_URL`, поэтому нельзя подтвердить живой вход в Telegram, доставку кода, миграции на вашей PostgreSQL или отправку в конкретные группы. Telegram выбирает канал доставки кода сам; `SentCodeTypeApp` означает, что код направлен в уже авторизованную сессию Telegram, а не гарантированно по SMS.

## Развёртывание

- Render Start Command: `python bot.py`
- Задайте `BOT_TOKEN`, `API_ID`, `API_HASH`, `DATABASE_URL`, `SUPER_ADMINS`.
- Запускайте только один экземпляр polling с данным `BOT_TOKEN`, иначе возможен `TelegramConflictError`.
- Не публикуйте токены, API_HASH, строку сессии Telethon, пароль 2FA или коды входа.
